## 一、YOLO26-pose 狗关键点检测能力评估

### 1.1 24 关键点定义

| 分区 | 关键点名称 | 数量 | 工作犬训练用途 |
|------|-----------|------|--------------|
| **前肢** | 左前爪、左前膝、左前肘、右前爪、右前膝、右前肘 | 6 | 坐/卧/立/行走姿势判定 |
| **后肢** | 左后爪、左后膝、左后肘、右后爪、右后膝、右后肘 | 6 | 坐(后膝角<90°)、卧(后肢伸展)判定 |
| **躯干** | 肩隆(withers)、喉咙(throat) | 2 | 整体姿态高度基准 |
| **尾部** | 尾根、尾尖 | 2 | 情绪/警觉状态指示 |
| **面部** | 鼻尖、下巴、左眼、右眼 | 4 | 注意力方向、吠叫判定 |
| **耳部** | 左耳根、右耳根、左耳尖、右耳尖 | 4 | 耳位情绪指示 |

### 1.2 动作覆盖评估

| 训练动作 | 判定逻辑 | 24点覆盖 | 置信度 |
|----------|---------|---------|--------|
| 坐 (Sit) | 后膝角<90° + 前肢直立 + 肩隆高度 | ✅ 全覆盖 | 高 |
| 卧 (Down) | 肩隆Y-后爪Y < 身高30% + 四肢伸展 | ✅ 全覆盖 | 高 |
| 立 (Stand) | 四肢延展 + 肩隆正常高度(基线) | ✅ 全覆盖 | 高 |
| 行走 (Walk) | 四足交替运动时序模式 | ✅ 全覆盖 | 高 |
| 小跑 (Trot) | 对角腿同步 + 速度模式 | ✅ 全覆盖 | 高 |
| 搜索嗅闻 (Search/Sniff) | 鼻尖Y > 肩隆Y(低于肩部) + 移动轨迹 | ✅ 全覆盖 | 高 |
| 吠叫 (Bark) | 鼻尖-下巴开合时序变化 | ⚠️ 部分覆盖 | 中 |
| 食物欲望 | 鼻尖-目标ROI距离变化率 | ✅ 全覆盖 | 高 |
| 胆量测试 | 接近/回避轨迹 + 身体姿态 | ✅ 全覆盖 | 中-高 |

### 1.3 关键限制

- **吠叫检测**：24 关键点无嘴部内唇/口角点，无法直接检测张嘴幅度。解决方案：额外训练 2 个嘴关键点，或通过鼻尖-下巴距离时序变化间接推断
- **目标较小**：工作犬训练场景的摄像头距离 5-15 米，犬只约 100-200 像素。YOLO26n-pose 在 640×640 输入下可检出

## 二、行为分类方案深度对比

### 2.1 五方案全景对比

| 维度 | 规则引擎 | LSTM | ST-GCN | Transformer | DeepEthogram |
|------|---------|------|--------|-------------|-------------|
| 数据类型 | 关键点几何 | 关键点时序 | 关键点+图 | 关键点+图 | 原始像素 |
| 冷启动 | ✅ 立即 | ❌ 需数据 | ❌ 需数据 | ❌ 需大量数据 | ⚠️ 需300帧 |
| 数据需求 | 0 | 500-1000序列 | 800-1500序列 | 2000+序列 | 300-500帧 |
| 精度 | 70-85% | 75-82% | **85-92%** | 87-93% | 80-88% |
| 推理速度 | **<2ms/帧** | <5ms/帧 | 5-15ms/帧 | 15-50ms/帧 | 10-30ms/帧 |
| 可解释性 | **极高** | 低 | **高** | 低 | 中 |
| 实现成本 | **低** | 低 | 中-高 | 高 | 中 |

### 2.2 分阶段推荐

```
Phase 1 (MVP, 4-6周): 
  规则引擎 + 关键点角度分析
  → 能识别: 坐/卧/立/走 四类基础动作
  → 精度: 70-85%
  
Phase 2 (4-6周):
  LSTM 轻量分类器
  → 替代50%+规则，提升泛化
  → 需要: 500+动作序列数据集
  → 精度: 75-82%
  
Phase 3 (8-12周):
  ST-GCN (参考 BCST-GCN 2026)
  → 建模关键点空间关联
  → 需要: 1500+动作序列数据集
  → 精度: 85-92%
```

**不推荐初上 Transformer**：数据需求 2000+ 序列，推理速度慢 15-50ms/帧，冷启动困难。

## 三、部署方案对比

### 3.1 三种部署方案

| 维度 | 原生 Python ✅ | Docker Compose | NVIDIA Docker |
|------|--------------|---------------|---------------|
| **目标用户** | **公安/海关/消防** | 远程协作团队 | Linux 服务器 |
| Windows 支持 | **原生** | WSL2 性能开销 | ❌ 不支持 |
| GPU 直通 | **直接** | 需 WSL2 配置 | 原生 |
| 部署复杂度 | **低** (pip install) | 中 (需 docker) | 高 |
| 环境一致性 | 中 | **高** | **高** |
| 一键分发 | ❌ 安装依赖 | ✅ docker-compose up | ✅ |

### 3.2 推荐：原生 Python 部署

理由：
1. 目标用户（公安/海关/消防）使用 Windows 环境为主
2. Docker Desktop 在 Windows 上的 GPU 支持需 WSL2，增加复杂度
3. 单机运行，无多节点需求
4. `pip install ultralytics fastapi uvicorn sqlalchemy` 一行装完核心依赖

## 四、工作犬评分体系调研

### 4.1 USPCA PDI 标准（美国警犬协会）

| 科目 | 满分 | 描述 | 可自动化比例 |
|------|------|------|------------|
| Obedience (服从) | 120 | 坐/卧/立/随行/召回 | 60% |
| Search (搜索) | 140 | 建筑物/车辆搜索 | 70% |
| Apprehension (扑咬) | 340 | 追踪/咬合/押解 | 25% |
| 总分 | 600 | 及格 448 (70%) | ~50% |

### 4.2 可自动化的评分维度

| 评分维度 | 量化公式 | 权重 | 检测方法 |
|----------|---------|------|---------|
| **动作准确度** | cosine_sim(实测姿态, 标准姿态) | 20% | 关键点几何对比 |
| **响应延迟** | t_指令发出 - t_动作开始 (帧数×帧间隔) | 15% | 时间戳差值 |
| **保持时长** | count(连续满足姿态条件的帧数) | 15% | 时序序列分析 |
| **搜索效率** | 检出数 / 搜索耗时 (检出/秒) | 20% | ROI 进入/离开分析 |
| **注意力集中** | angle(头部方向向量, 训导员方向) 均值 | 10% | 鼻尖-双眼方向向量 |
| **胆量/欲望** | 1 - min_distance(鼻尖, 目标) / max_distance | 10% | 距离变化曲线 |
| **步态质量** | 步幅标准差 / 平均步幅 (变异系数) | 10% | 足部关键点轨迹 |

### 4.3 评分等级映射

| 维度得分 | 1-3 | 4-6 | 7-8 | 9-10 |
|---------|-----|-----|-----|------|
| 含义 | 需改进 | 合格 | 良好 | 优秀 |

**总分 = Σ(维度分 × 权重)，满分 10 分制。**
