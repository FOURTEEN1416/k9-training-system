| 数据资产 | 现状 | 阻塞点 |
|---------|------|--------|

| **Mamba 基线** | 合成数据 85.61% | 同样需真实数据验证 |
| **ReID 微调** | APTv2 Canidae 12 ID | 数据不足（HANDOVER P2） |

### 2.2 三条候选技术路线（源自调研）

**路线 A：半监督自训练（TCL 风格）—— 最贴合对话方案 B**
- 原理：少量真实标注（锚点）+ 大量无标注数据，通过时序对比学习 + 伪标签自训练迭代
- 代表：TCL (CVPR 2021) 在 UCF101 上 10% 标注达 82.7%（接近全监督 88.6%）
- 本项目落地：规则引擎 8 类几何判定 → 生成种子标签（seed）→ ST-GCN+BC 自训练 → 置信度阈值筛选 → 迭代
- 优点：无人工标注成本，与现有 pyskl pipeline 无缝
- 风险：规则引擎种子标签质量决定上限（当前合成 46.97% 说明规则-学习域差大）

**路线 B：无监督行为发现（keypoint-MoSeq / VAME）+ syllable 人工映射**
- 原理：关键点序列 → 无监督发现刻板运动单元（syllables）→ 人工映射到 22 行为类
- 本项目现状：kpm 已训练（43 syllables），32 已映射但**几乎全是 down**——InterPet4D 数据以卧为主，类覆盖不足
- 优点：已有训练产物，仅需补映射
- 风险：syllable 与行为类别粒度不对齐；InterPet4D 覆盖 P0 有限，P1/P2 无法覆盖

**路线 C：主动学习标注管线（DeepEthogram / small-text 思路）—— 最小化人工标注**
- 原理：模型先推理全部 682 片段 → 不确定性采样（熵/边界）挑出最难的 N 个 → 人只标这 N 个 → 重训 → 迭代
- 代表：DeepEthogram 内置 GUI + Kinetics700 预训练（帧级）
- 本项目落地：现有 ST-GCN+BC（合成）推理 682 片段 → 熵排序 → Label Studio 标 top-100 → 重训 → 迭代 2-3 轮
- 优点：把"标 682 片段"压缩为"标 100-200 片段"，且每轮标注都对准模型弱点
- 风险：初始模型太弱（46.97%）时不确定性采样信号差，需先用规则引擎粗标预热

**路线 D：LLM 辅助自动标注（AmadeusGPT 思路）—— 加速器**
- 原理：自然语言行为描述（如"坐：后腿折叠+前腿伸直+持续2秒"）→ LLM 生成代码 → 批量自动标注
- 本项目落地：实验室阶段 Agnes API（已豁免）+ 本地规则函数库，把 22 类行为的中文描述转成时序逻辑代码
- 优点：与物理-语义解耦思想同构，标注规则可解释、可复用
- 风险：LLM 生成代码需人工审查；行为定义复杂时生成质量不稳定

## 3. 推荐方案：四线组合（对话方案 B 为主干）

### 3.1 总体策略

```
Phase A（数据种子）: 规则引擎几何判定 → 核心公开无标签池粗标签（P0 8 类为主）
    ↓
Phase B（主动学习标注）: ST-GCN+BC（规则预热后）推理 → 熵排序 → Label Studio 标 top-N
    ↓ 迭代 2-3 轮
Phase C（半监督自训练）: 标注集 + 无标注集 → TCL 风格时序对比自训练 → 置信度阈值筛选
    ↓
Phase D（验证闭环）: 真实数据验证 ST-GCN+BC ≥ 85% / Mamba ≥ 85% → 数据阻塞解除
```

### 3.2 关键决策点（需用户确认）

| # | 决策点 | 选项 | 建议 |
|---|--------|------|------|
| 1 | 种子标签来源 | A. 规则引擎粗标 | **建议 A**（零成本、可解释，与 YAML 评分卡同构） |
| 2 | 人工标注量 | A. 0（全自动自训练）/ B. 100-200 片段 / C. 全 682 | **建议 B**（主动学习只需最少人工，质量有保障） |
| 3 | 标注工具 | A. Label Studio（已有）/ B. DeepEthogram GUI | **建议 A**（已部署，且有 YOLO26-pose 预标注基础） |
| 4 | 半监督方法 | A. TCL 复现 / B. 自研伪标签自训练 | **建议 B**（TCL 是 RGB 视频方法，骨架域需适配；自研更贴合现有 pipeline） |
| 5 | LLM 辅助标注 | A. 启用 Agnes API / B. 暂不启用 | **建议 A**（实验室阶段已豁免，可显著降低人工标注量） |
| 6 | keypoint-MoSeq 处置 | A. 继续补映射 / B. 存档废弃 | **建议 B**（InterPet4D 类覆盖不足，P1/P2 无法覆盖，投入产出比低） |

### 3.4 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 规则引擎种子标签噪声大 | 60% | 高 | 仅作预热；主动学习熵采样可纠偏；多专家一致性校验 |
| 主动学习初始模型太弱（46.97%） | 50% | 中 | 先用规则引擎粗标全量做 warm-start，再进入熵采样 |
| YouTube 视频场景单一（5 个源） | 70% | 中 | 补充 APTv2 犬类视频 + InterPet4D 片段扩充无标注池 |
| LLM 生成标注规则不稳 | 40% | 低 | 人工审查 + 规则库沉淀，LLM 仅作草稿 |
| 伪标签确认偏差放大 | 50% | 高 | 不确定性估计 + 人工复核 top 不确定样本（对话坑点 2 应对） |

## 4. 结论

1. 对话.txt 中**方案 B（小样本自监督数据飞轮）**与项目最契合，可直接作为数据问题解决主干
2. **物理-语义解耦**思想项目已天然具备（关键点物理层 + YAML 语义层），无需新架构
3. 此前 kpm/弱监督路径未走完闭环，**不建议继续投入**（类覆盖不足）
4. 推荐 **规则种子 → 主动学习 → 半监督自训练** 三阶段组合，人工标注量从 682 压缩到 100-200
5. LLM 辅助标注作为加速器（实验室 Agnes API 已豁免），与 AmadeusGPT 思路同构但本地化改造
