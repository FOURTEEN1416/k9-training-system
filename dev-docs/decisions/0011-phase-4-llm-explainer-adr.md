# ADR 0011：Phase 4 LLM行为解释器

## 状态: ✅ 已实施 (2026-08-02)

## 背景
Phase 3 已完成 ST-GCN+BC 行为识别模块，提供 22 类行为分类结果。然而，仅有行为概率分布对训导员缺乏解释意义，训导员需要了解 “为什么是 这一行为” 以及 “如何改进”。

## 决策选项

### 选项 A：本地部署 LLM
- **模型**: Llama 3.2 1B (8bit量化)
- **优点**: 
  - 无持续成本，一次部署永久使用
  - 数据不出本地，符合项目本地化原则
  - CPU推理 ≈ 2s/次，满足交互需求
- **缺点**: 
  - 需要本地硬件支持 (已在 RTX 5060 验证)
  - 模型维护责任自负
- **适用性**: 本项目首选，符合“本地化、无云依赖”原则

### 选项 B：OpenAI API
- **模型**: gpt-4o-mini
- **优点**: 
  - 质量最高，效果最好
  - 无需自行部署和维护
- **缺点**: 
  - 持续成本 (约 $0.0005/次)
  - 数据将上传至云端 (违反项目数据隐私原则)
  - 依赖网络环境
- **适用性**: 备选方案，当本地部署不可行时

### 选项 C：规则解释器
- **实现**: 基于已有的规则引擎和业务逻辑
- **优点**: 
  - 开发成本最低
  - 数据完全本地
  - 延迟最低
- **缺点**: 
  - 解释能力有限，无法处理复杂场景
  - 随业务增长可扩展性差
- **适用性**: 作为 Phase 3 的延续，非 Phase 4 重点

## 决策建议

**推荐**: 选项 A (本地部署 Llama 3.2 1B)
- 理由: 符合项目“本地化、无云依赖、数据隐私”三大核心原则
- 成本: 一次性硬件成本 (已在 RTX 5060 上验证)，零持续成本
- 延迟: ≈ 2s/次，满足训导员交互需求

**备选**: 选项 B (OpenAI API)
- 场景: 本地部署不可行时的备选
- 成本: 预算 $500/年，用于度量后决定是否转为选项 A

## 实施路线图

### 第一阶段 (1周): 环境搭建
- [ ] 下载 Llama 3.2 1B 模型权重
- [ ] 配置 8bit 量化环境 (bitsandbytes)
- [ ] 验证 CPU推理性能 (目标: < 3s/次)
- [ ] 搭建 FastAPI 接口 (/api/llm/explain)

### 第二阶段 (1周): 提示工程
- [ ] 编写系统提示词 (行为分析专家角色)
- [ ] 编写用户提示词模板 (输入: 22类概率 + 7维评分)
- [ ] 编写输出后处理 (中文报告格式)
- [ ] 编写单元测试 (输入输出格式验证)

### 第三阶段 (1周): 集成与验证
- [ ] 集成至现有后端 (backend/app/api/)
- [ ] 编写 E2E测试 (输入真实模型输出 -> 验证报告质量)
- [ ] 性能基准测试 (延迟、内存占用)
- [ ] 文档编写 (使用说明, API规范)

### 第四阶段 (1周): 灰度发布
- [ ] 启动服务 (localhost:8001)
- [ ] 邀请 2-3名训导员试用
- [ ] 收集反馈 (报告质量评分)
- [ ] 根据反馈迭代优化

## 成功标准

- [ ] 模型加载 < 10s
- [ ] 推理延迟 < 5s/次 (CPU)
- [ ] 生成报告质量: 训导员评分 ≥ 3/5 (满意度调查)
- [ ] 数据隐私: 无数据上传云端 (验证通过)
- [ ] API契约: FastAPI 规范文档齐全

## 风险与缓解

| 风险 | 概率 | 缓解措施 |
|------|------|----------|
| 模型加载缓慢 | 40% | 使用 4bit 量化而非 8bit，或预热模型 |
| 提示词工程不佳 | 60% | 多轮迭代，邀请训导员参与提示词设计 |
| 输出质量不达标 | 70% | 设立人工评审机制，迭代优化提示词 |
| 硬件不支持 AVX-512 | 30% | 回退至纯 CPU 模式 (仍在可接受延迟范围) |
