# ADR 0016：生产受阻时的应急预案（产品定位【不降级】）

## 状态: 📋 草案（2026-10-19，待用户确认）

> 性质: **工程侧应急预案**。只约束工程团队在触发条件下的行为，**不改变产品定义**。
> 上位文档: `dev-docs/production-readiness-gap-plan.md`（§8 依赖与风险 :223-230、
> §12 待用户裁决 :271-277）、`dev-docs/decisions/0015-k9-bench-v0-protocol.md`（ADR 0015）。
> 裁决权: 产品定位的最终裁决权归用户（gap-plan §12:271-277；ADR 0015 §9）。
> 本 ADR 只回答“工程侧在等用户裁决期间不得做什么、可以做什么”。

---

## 0. 立场句

**产品定位【不降级】。**

`gap-plan:224` 列出的「否则将目标降级为『审计型规则引擎产品』」是一个**风险后果描述**，
不是已生效决策；本 ADR **明确否决**把它作为工程默认路径。
在用户以新 ADR 显式裁定之前：

- 产品定义、路线图、A3 目标（`gap-plan:36`）**保持不变**；
- 工程侧只能**收缩对外承诺范围**（只承诺已验收能力），不能改写产品定位；
- 禁止把「审计型规则引擎产品」写入产品定位、路线图、品牌、对外文案或验收标准。

## 1. 触发条件

以下任一条成立即进入本预案。**日期与判定人由用户指定，本 ADR 不自行拍数**
（避免工程侧用自设日期制造既成事实）。

| ID | 触发条件 | 来源 | 判定口径 |
|----|----------|------|----------|
| T1 | 首批真实视频入库逾期 | `gap-plan:273`（§12-1） | 以用户裁决的采集计划截止日为准；逾期 = 计划日期已过且入库量为 0 |
| T2 | ADR 0015 §9:81-87 的三条生效条件在约定期限内一条未满足 | ADR 0015 §9 | 三条 = ①§2 五项待定项裁决；②首批真实视频入库 + splits.json；③双标一致性抽检通过 |
| T3 | 标注人力排期未落实 | `gap-plan:226` | 用户确认的排期表缺失或连续两个周期无人力投入 |
| T4 | 目标部署机未定 | `gap-plan:276`（§12-4） | 用户未在约定期限内选定本机工作站 / 基地 GPU 机 / Jetson |

> 触发判定必须留痕：写入 `reports/` 下的当次记录，并引用用户书面裁决或排期表。
> 工程侧不得以“看起来快逾期了”自行宣布触发。

## 2. 预案条款

| ID | 条款 | 约束内容 |
|----|------|----------|
| C1 | **报告口径不降级** | 每份对外报告必须包含识别模式、模型版本、数据来源、复核标记；缺任一字段即不得发布（ADR 0015 §7；P0-5 报告溯源）。 |
| C2 | **识别模式锁 `rule_only`** | 真实 K9-Bench-v0 未过线前，生产默认 `rule_only`（`config.py:221-225`）；**禁止用合成数字切换到 `vote` / `primary_*`**（`gap-plan` §1 反验收 + ADR 0015 §6）。 |
| C3 | **只收缩承诺范围，不改产品定义** | 可把对外承诺限定为“已验收能力”（如：本地化部署、可审计报告、基地隔离）；**不改变产品定义、路线图与 A3 目标**。禁止把「审计型规则引擎产品」写入产品定位/路线图/品牌。 |
| C4 | **合成数据只进工程回归** | 合成数据不得进入 K9-Bench-v0（ADR 0015 §2 硬性排除）；只能用于管线回归与性能基线。 |
| C5 | **全本地数据纪律** | 标注、训练、推理、报告全部本地；不上传云端、不外包标注（`gap-plan:225`）。 |
| C6 | **不放宽门槛** | 70% / 85% 部署门槛不得因进度压力下调（ADR 0015 §6:57-65）；未达标类别保持 rule/人工。 |
| C7 | **协议变更只能新版本号** | K9-Bench-v0 的切分/指标/门槛任何修改必须 v0.x→v0.y 新版 + 书面理由（ADR 0015 §8:74-79）。 |
| C8 | **密钥轮换是发布硬门** | 曾泄露的 DB 密码 / Label Studio 密码 / JWT secret 必须完成轮换且旧 JWT 失效；**泄露密钥仍有效即阻塞发布**（`gap-plan:228`，P0-1）。 |
| C9 | **论文负结果 / R16 / P4 边界必须引用** | 对外材料涉及识别能力时必须引用论文负结果与 R16/P4 边界，**禁止合成指标冒充**（`gap-plan:230`；ADR 0015 §8）。 |

## 3. 回退路径

| ID | 路径 | 边界 |
|----|------|------|
| R1 | **维持 `rule_only` 运营** | 产品定义不变；报告如实标注“自动识别·建议人工复核”；不得宣称深度模型主路径。 |
| R2 | **移植 gap-plan §7 研究线（选项）** | 仅属工程/研究增强，**不是数据替代**；移植后仍须在 K9-Bench-v0 重新验收（`gap-plan:216`），不得绕开 A3；跨仓只允许文档指针与显式移植，禁止直接 import。 |
| R3 | **只有用户以新 ADR 显式裁定才可改写产品定位** | 工程侧不得自行降级、不得以“临时口径”变相降级；新 ADR 须写明生效日期与影响范围。 |

## 5. 失效与复查

1. **失效条件**（任一成立则本 ADR 自动失效，回到用户裁决）：
   - 用户以新 ADR 裁定产品定位；
   - ADR 0015 转 ✅ 生效并冻结，且 T1–T4 全部关闭；
   - 发布的对外承诺与实际验收能力不一致（触发 §6 复核）。
2. **复查节奏**：每 4 周一次，由工程侧出具一页状态：
   T1–T4 判定、A1–A5 进度、C1–C9 是否有违反、Blocker 变化。
3. 复查记录写入 `reports/`，不得只存在口头/聊天记录。

## 7. 后果

- 工程侧在等待用户裁决期间有明确的“不可做”清单（C1–C9），避免用进度压力
  换取口径放宽或指标美化。
- 发布检查单（`docs/release-checklist.md`）把 C8 与审计日志缺口列为 Blocker，
  与本 ADR 的失效条件一致。
- 本 ADR 不产生任何代码改动；它约束的是报告口径、部署模式、数据边界与对外承诺。
