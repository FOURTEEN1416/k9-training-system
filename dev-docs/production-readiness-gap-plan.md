# K9 生产可用性差距整改方案（Production Readiness Gap Plan）

> **状态**: v1.0 草案（2026-09-19，用户目标对齐后产出）
> **Owner**: `dev-docs/production-readiness-gap-plan.md`
> **定位**: 本仓从「研究验证平台」到「生产可用系统」的唯一整改路线图
> **用户目标（2026-09-19）**: **生产可用（含真实识别精度）**
> **用户痛点**: ①识别/评分不可信 ②服务起不来/环境太脆 ③产品功能不完整 ④真实工作犬数据/模型缺失
> **性质**: 计划 truth；执行须按 AGENTS 硬规则（无新鲜验证无完成声明），证据归 `reports/`
> **边界**: 不替代 Phase 0-3 关闭结论；不把合成层指标当作生产验收；研究线能力移植另见 §7

---

## 0. 一句话结论

工程骨架（API / Celery / 评分 YAML / RBAC / 前端 5 页）**存在**，但生产可用被四条链同时卡住：

| # | 缺口 | 根因 | 后果 |
|---|------|------|------|
| G1 | 真实工作犬**带行为标签**数据几乎不存在 | 公开集无 K9 逐段行为标签；内部采集未落地 | 模型无法过 vote/primary 线 |
| G2 | 行为识别真实精度未验收 | ST-GCN+BC 合成 46.97%；E2E 3.1d SKIP | **评分不可信** |
| G3 | 多服务环境脆 + 安全债 | PG/Redis/Celery/Node 强依赖；public 历史泄露密钥 | **起不来 / 不敢上线** |
| G4 | 产品闭环缺训练员工作流 | 无完整登录/标注/微调工作台；头部仍写 Phase 0 骨架 | **功能不完整** |

**关键认知**：G1 是 G2 的前置；没有 G1，任何「生产识别精度」承诺都不成立。G3/G4 可与 G1 并行。论文线 R16/P4 已独立证实：公开动物骨架域端到端仍近随机——**产品不能指望「再跑一次合成实验」变生产可用**。

## 1. 生产可用定义（验收总纲）

系统同时满足以下五条，才可宣布「生产可用」：

| ID | 标准 | 可测判据 |
|----|------|----------|
| A1 | **可启动** | 干净 Windows 上按文档一条命令链起全服务；健康检查 `/health` 与前端「后端在线」稳定；密钥来自 `.env`，`APP_ENV=production` 可过校验 |
| A2 | **可登录可分工** | 至少 ADMIN / MANAGER / HANDLER / VIEWER 四角色前端登录可用；基地数据隔离抽测通过 |
| A3 | **识别可信** | 在**冻结的真实 K9 测试集**上：主行为类 top-1 ≥ **70%** 才允许 `vote`；≥ **85%** 才允许 `primary_*`（与 `router.py` 既有门槛一致）；报告必须附 per-class 与混淆矩阵 |
| A4 | **评分可解释** | 每条评分维度可追溯到 behaviors/signals；报告含模型版本、识别模式（rule/shadow/vote/primary）、置信度摘要；低置信自动标注「需人工复核」 |
| A5 | **可回流** | 训练员可在产品内对 episode 做「对/错/改标签」；修正数据可导出为训练格式；微调任务可触发并产出新模型版本记录 |

**反验收（禁止）**：
- 用合成层准确率代替真实 K9 测试集宣称生产达标
- 在识别未过线时默认 `primary_stgcn` / `primary_mamba`
- 隐藏规则引擎/影子模式，让报告看起来像深度模型结果
- 继续使用 git 历史中已泄露的 DB 密码 / JWT secret

## 2. 差距矩阵（现状 → 生产）

| 维度 | 现状（证据） | 生产要求 | 差距等级 |
|------|--------------|----------|----------|
| 姿态检测 | YOLO26-pose APTv2 微调 Box mAP50=96.1%（公开动物域） | 真实训练场视频上关键点覆盖率/置信度达标 | 🟡 中：检测尚可，域偏移未系统评估 |
| 行为识别 | 规则引擎主路径；ST-GCN 合成 46.97%；Mamba 合成 85.61%；真实 K9 无验收数字 | 冻结测试集 ≥70% / ≥85% 分级部署 | 🔴 阻塞 |
| 多犬追踪 | APTv2 24 视频双达标 5/24 | 单犬场景先可用；多犬评分场景明确降级策略 | 🟠 高（多犬评分勿默认开启） |
| 3D 姿态 | MPJPE 21.74mm（InterPet4D 配对管线） | 非生产评分主路径；可标为可选 | 🟢 低 |
| 评分引擎 | FCI-IGP / USPCA / 选育 YAML + PDF | 绑定识别模式与复核标记；维度可追溯 | 🟠 高 |
| LLM 解释 | Agnes API 实验室阶段 | 本地化或明确「辅助文案」定位，不参与分数 | 🟡 中 |
| 延迟 | FCI 0.63x / USPCA 0.88x / SHADOW 1.13x；pose 占 96% | 抽帧/TRT/批处理；试点写明 SLA（如 ≤1x 视频时长） | 🟠 高 |
| 数据 | uploads ~33 段；无规模化真实行为标注集 | **真实 K9 标注飞轮**（见 §4） | 🔴 阻塞 |
| 环境 | 多服务手工启动；依赖文档长 | 一键启动脚本 + 健康检查 + 失败诊断 | 🔴 阻塞 |
| 安全 | public 历史泄露口令/JWT；config 已改为占位符 | 密钥轮换 + production 校验通过 + `.env` 不入库 | 🔴 阻塞 |
| 产品 UI | 5 视图；无完整登录/标注/微调工作台 | 训练员闭环（§5） | 🟠 高 |
| 可复现训练 | scripts 齐；真实数据链未打通 | 标注→数据集版本→训练→评估→注册模型 | 🔴 阻塞 |

## 3. 优先级总览

```
P0（1-3 周）  诚实可运行的生产底座 + 数据/评测协议冻结
     ↓        （没有 P0，后面全是空转）
P1（3-8 周）  真实标注飞轮 + 识别过线 + 产品闭环 + 评分可信化
     ↓        （达到「基地试点可用」）
P2（+数周）   多犬/延迟/边缘部署/多基地规模化 → 生产发布
```

研究线 PSD 迁移（§7）**不进 P0 关键路径**，仅作为 P1 数据不足时的增强选项。

## 4. P0 — 可运行底座与协议冻结

> 目标：系统**能稳定起来、能安全跑、评价标准先写死**。识别精度尚未达标，但系统可作为「规则引擎 + 人工复核」模式下的**可审计试点工具**。

### P0-1 安全与配置基线
| 任务 | 内容 |
|------|------|
| 动作 | 轮换 PostgreSQL 密码、（若用过）Label Studio 密码、全新 `AUTH_SECRET_KEY`（≥32 字符）；`.env` 确认不入库；清理/拒绝泄露值；`APP_ENV=production` 启动自检通过 |
| 验收 | `config.py` 校验逻辑下 production 启动成功；git status 不含 `.env`；单元/配置测试绿 |
| 依赖 | 用户本机 DB 权限 |
| 痛点 | ②④ |

### P0-2 一键启动与健康检查
| 任务 | 内容 |
|------|------|
| 动作 | PowerShell 启动编排：Redis → PG 探活 → Alembic → Celery → FastAPI → 前端；失败时打印缺失项（端口/权重/密钥）；`/health` 聚合 DB/Redis/模型路径状态 |
| 验收 | 干净文档步骤下，目标机 15 分钟内全绿；故意停 Redis 时 health 能指名故障 |
| 依赖 | P0-1 |
| 痛点 | ② |

### P0-3 冻结真实评测协议（先于一切刷分）
| 任务 | 内容 |
|------|------|
| 动作 | 定义 **K9-Bench-v0**：来源（用户提供的真实训练/考核视频）、切分（按犬/按场次防泄漏）、标签 schema（与 22 类/规则引擎/P0-P2 分层对齐）、指标（top-1、macro-F1、per-class、边界 F1）、部署门槛 70%/85%、报告格式；预注册文档 `dev-docs/decisions/` 或 `docs/` |
| 验收 | 协议签字版入库；样本清单与标签规范可执行；**禁止测试集进训练** |
| 依赖 | 用户确认视频来源与保密级别 |
| 痛点 | ①④ |

### P0-4 模型与权重盘点
| 任务 | 内容 |
|------|------|
| 动作 | 盘点 `runs/` 与 `data/models`：YOLO / ST-GCN / Mamba / ONNX 是否完整可加载；缺的在文档中标明「不可部署」；`behavior_deploy_mode` 默认值定为 **`rule_only`**（生产未达标前） |
| 验收 | 启动时模型缺失不崩溃，路由降级有日志；默认模式文档与代码一致 |
| 依赖 | 无 |
| 痛点 | ①② |

### P0-5 评分可信化底线（无 ML 精度也可先做）
| 任务 | 内容 |
|------|------|
| 动作 | 报告头固定三字段：识别模式、模型版本、置信度摘要；低置信/规则引擎结果标注「自动识别·建议人工复核」；评分维度 → episode/signal 溯源 API 或报告附录 |
| 验收 | 任一 PDF/API 结果可回答「这个分从哪来、用了哪个模型、是否需复核」 |
| 依赖 | 评分引擎已有；改动报告模板与 API schema |
| 痛点 | ① |

### P0-6 产品最小闭环（生产底座版）
| 任务 | 内容 |
|------|------|
| 动作 | 前端登录页 + JWT 会话；去掉「Phase 0 · 骨架」误导文案，改为真实版本号与当前识别模式；犬只档案 CRUD 从 Admin 提升为可用工作台入口；Handler 视角：选犬→传视频→看状态→下报告 |
| 验收 | 四角色至少 HANDLER/ADMIN 全流程手测通过；错误态（未登录/无权限/视频失败）可读 |
| 依赖 | P0-1、P0-2 |
| 痛点 | ②③ |

**P0 出口**：A1 + A2 + A5 的导出骨架 + A4 底线满足；系统以 `rule_only` 模式在真实视频上出**可审计**报告。识别仍可能不准，但**不再假装是生产模型**。

## 5. P1 — 数据飞轮 + 识别过线 + 产品完整

> 目标：**基地试点可用**，并向生产 A3 推进。关键路径 = 标注 → 训练 → 评估 → 切换部署模式。

### P1-1 真实 K9 标注飞轮（关键路径）
| 任务 | 内容 |
|------|------|
| 动作 | ①采集/整理真实工作犬训练与考核视频（数量目标见下）；②产品内或旁路工具完成行为段标注（起止 + 类别）；③YOLO 提点 → 与标签对齐 → 导出训练格式（pyskl/项目 dataset）；④数据集版本号 + 许可/保密台账 |
| 建议规模（启动） | 每优先行为类 ≥50–100 个有效 episode；总量争取 **300–1000+ episodes**，覆盖 P0 全类 + 高频 P1；P2 高级科目可后置 |
| 验收 | 可训练数据集落盘 + 清单报告；标注一致性抽检（双标 kappa 或人工抽检） |
| 依赖 | **用户/基地侧视频与人力**——本仓无法凭空生成真实 K9 标签 |
| 痛点 | ④① |

### P1-2 标注与微调产品功能
| 任务 | 内容 |
|------|------|
| 动作 | 前端：episode 时间轴审核（接受/拒绝/改类/改边界）；后端：annotations/finetune API 补齐权限与状态机；训练任务 Celery 化；模型注册 + 版本 + 指标卡片 |
| 验收 | A5 全满足：修正→导出→训练→新模型入库可在系统内完成或有一键脚本 |
| 依赖 | P0-6、P1-1 至少首批数据 |
| 痛点 | ③④ |

### P1-3 识别训练与过线
| 任务 | 内容 |
|------|------|
| 动作 | 在 K9-Bench-v0 上训练/微调 ST-GCN+BC 与/或 Mamba 轨；输出 per-class；与规则引擎对比；达 **≥70%** 后配置 `vote`；达 **≥85%** 后才配置 `primary_*`；未达标类保持规则/人工 |
| 验收 | `reports/k9-bench-v0-*.md|json` 新鲜评估归档；部署模式切换有书面依据 |
| 依赖 | P0-3、P1-1 |
| 痛点 | ①④ |

### P1-4 单犬生产路径强化
| 任务 | 内容 |
|------|------|
| 动作 | 真实场地视频上姿态覆盖率评估；抽帧 stride / 置信度过滤；失败样本回流标注；SHADOW 日志对比规则 vs 模型 |
| 验收 | 代表性真实视频 pose 成功率报告；对比日志可分析 |
| 依赖 | P0、真实视频 |
| 痛点 | ①② |

### P1-5 评分业务验收
| 任务 | 内容 |
|------|------|
| 动作 | 邀请训练员/评审对 10–20 份报告人工对照：自动分 vs 人工 FCI/USPCA 口径；记录偏差模式；回调评分卡权重或识别类映射 |
| 验收 | 书面验收：哪些科目可自动、哪些必须人工；偏差表入库 |
| 依赖 | P1-3 至少 vote 级或高质量规则+复核 |
| 痛点 | ① |

### P1-6 运维与延迟（试点级）
| 任务 | 内容 |
|------|------|
| 动作 | 日志与失败原因产品化；视频处理进度可靠；pose 抽帧参数可配；记录 P95 处理时长 |
| 验收 | 试点一周：失败可诊断；时长统计报告 |
| 依赖 | P0-2 |
| 痛点 | ② |

**P1 出口**：A3–A5 在**试点范围**内满足（或明确未过线类降级）；系统进入基地试点。

## 7. 研究线（PSD）移植 — 选项，非 P0 关键路径

| 能力 | 移植价值 | 前提 | 建议时机 |
|------|----------|------|----------|

## 8. 依赖与风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| **无真实标注视频** | P1 无法启动，生产 A3 永远达不到 | 用户侧采集计划为最高优先级外部依赖；否则将目标降级为「审计型规则引擎产品」 |
| 保密/公安场景数据 | 不能用公开集充数；标注工具需本地 | 全本地飞轮；不上传云端 |
| 标注人力不足 | 类覆盖不均 | 先保 P0 八类 + 高频科目；长尾类规则/人工 |
| 算力仅 RTX 5060 8GB | 大模型/长视频慢 | 抽帧、小骨干、ONNX、错峰训练 |
| 泄露密钥仍有效 | 安全事故 | P0-1 强制轮换，旧 JWT 失效 |
| 用合成指标汇报 | 业务误判可用 | 反验收条款 + 报告强制标注数据来源 |
| 论文负结果被忽视 | 低估数据难度 | §0 与 §7 引用 R16/P4 边界 |
