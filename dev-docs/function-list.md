## 功能详单

### F1: 视频上传与管理

- **用户**：训导员
- **输入**：视频文件（mp4/avi/mov）+ 测试类型（选育食物/选育玩具/选育胆量/科目测评）
- **输出**：视频元数据存储、异步推理任务
- **权限**：训导员上传自己的视频
- **正常路径**：上传 → 元数据入库 → 触发异步推理 → 状态更新
- **异常**：格式不支持、文件过大、网络中断
- **边界**：Phase 1 仅支持文件上传，RTSP 在 Phase 3

### F2: 姿态检测（YOLO26-pose）

- **用户**：系统自动
- **输入**：视频帧序列
- **输出**：24 关键点坐标序列（每帧）+ 检测置信度
- **权限**：内部服务
- **正常路径**：视频解码 → 逐帧推理 → 关键点序列化 → 入库
- **异常**：犬只遮挡、画面模糊、多犬干扰
- **边界**：Phase 1 单犬，Phase 3 多犬追踪
- **现状**：✅ best.pt 已微调（Pose mAP50=0.9239, mAP50-95=0.5167）

### F3: 行为识别（双场景）

#### F3a: 选育信号提取器

- **用户**：系统自动
- **输入**：关键点序列 + 检测框 + 物体检测（COCO 球/食物类）
- **输出**：选育信号字典
  - 食物欲望：approach_latency, approach_speed, sniff_duration
  - 玩具欲望：chase_latency, chase_speed, hold_duration
  - 胆量：retreat_distance, freeze_duration, recovery_time
- **权限**：内部服务
- **正常路径**：关键点轨迹 → 速度/距离/静止时长计算 → 信号字典
- **异常**：物体未检测到、关键点缺失
- **边界**：Phase 1 原型级（受控环境），Phase 2 精化

#### F3b: 科目规则引擎

- **用户**：系统自动
- **输入**：关键点序列
- **输出**：行为类别 + 时间区间 + 置信度（8 类：坐/卧/立/随行/坐立/停留/叫/咬）
- **权限**：内部服务
- **正常路径**：关键点几何规则 → 行为分类
- **异常**：关键点缺失、行为未知、置信度过低
- **边界**：Phase 1 规则 8 类，Phase 2 扩展 16 类，Phase 3 ST-GCN+BC 22 类

### F4: 评分引擎（YAML 配置化）

- **用户**：系统自动 + 训导员配置
- **输入**：行为识别结果 + 评分卡 YAML 配置
- **输出**：多维评分 + 标签 + 命中规则
- **权限**：内部服务（评分）；训导员（配置修改）
- **正常路径**：加载 YAML 评分卡 → 提取信号 → 规则匹配 → 加权汇总
- **异常**：评分卡语法错误、信号缺失
- **边界**：Phase 1 双场景评分卡（选育 3 维 + 科目 5 维）
- **关键特性**：
  - YAML 配置化（训导员可改阈值/权重）
  - 热加载（改配置不重启服务）
  - 可解释（每条评分给出命中规则 + 标签）
  - 场景隔离（选育评分卡 vs 科目评分卡独立）

### F5: 评分报告生成

- **用户**：训导员
- **输入**：评分结果 + 视频元数据 + 关键帧
- **输出**：PDF 报告 + 可视化标注视频
- **权限**：训导员查看自己的报告
- **正常路径**：评分结果 → reportlab 模板渲染 → PDF 导出 + 标注视频生成
- **异常**：模板渲染失败、视频处理失败
- **边界**：Phase 1 PDF，Phase 2 加 CSV + 可视化标注

### F6: 犬只档案管理

- **用户**：训导员
- **输入**：犬只信息（品种、年龄、训练阶段）
- **输出**：犬只档案 CRUD
- **权限**：训导员管理自己犬只
- **正常路径**：CRUD 操作
- **异常**：重复 ID、必填缺失
- **边界**：Phase 1 基础 CRUD

### F7: 模型与评分卡管理

- **用户**：系统管理员
- **输入**：模型权重、评分卡 YAML
- **输出**：模型版本管理 + 评分卡版本管理
- **权限**：仅管理员
- **正常路径**：注册模型 / 修改评分卡 → 版本记录 → 切换/对比
- **异常**：权重损坏、YAML 语法错误
- **边界**：Phase 1 基础版本注册（无 A/B 对比）

## 大阶段计划

> 详细 stage-plan 见 `stage-plan.md`

| 阶段 | 交付流程 | 验收标准 |
|------|---------|---------|
| Phase 0 | ✅ 完成（2026-07-26） | 环境可运行、DB schema 就位、前后端骨架启动 |
| Phase 1 | MVP 端到端闭环（双场景） | 1 段选育视频 + 1 段测评视频 → 2 份评分 PDF |
| Phase 2 | 数据飞轮 + 16 行为 + 基地合作 | 工作犬数据微调 + USPCA 映射 |
| Phase 3 | 专业功能 | ST-GCN+BC + 多犬 + 3D + FCI-IGP |
| Phase 4 | 前沿方法（按需） | LLM / Transformer-Mamba / RL |

**大阶段原则**（来自 sliver-vibe-coding）：
- 每个大阶段让至少一个用户角色完成一个有意义的产品流程
- 不允许"仅登录"这种过小阶段
- 不允许包含多个不相关用户角色的过大阶段
